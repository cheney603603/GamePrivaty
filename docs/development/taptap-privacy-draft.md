## 当前版本功能与信息处理

### 游戏进度与设置

游戏会在设备本地保存进度、设置和引导状态，以支持继续游戏。当前代码使用本地存储，没有在游戏领域逻辑中发现自建游戏账号或游戏进度上传接口。Android Manifest 开启了系统应用备份（`allowBackup=true`），因此设备或操作系统的备份能力可能影响本地数据的保存与恢复；正式发布前需确认是否保留该设置，并说明适用情况。卸载应用可能导致本地存档丢失。

### TapTap 登录、实名认证与防沉迷

Android 工程依赖 TapTap SDK 4.11.0 的 `tap-core`、`tap-login`、`tap-compliance` 模块。代码设计为用户阅读并同意已配置的隐私政策后，点击 TapTap 登录按钮才初始化 SDK；登录申请 `basic_info` 范围，游戏读取 TapTap 账号 OpenID 并将其交给 TapTap 合规服务启动实名认证和防沉迷流程。游戏本身没有姓名或身份证号码输入界面，也没有在当前接入代码中自行保存这些证件信息。

当前仓库的 `configs/taptap.example.json` 中 `privacyUrl`、`privacyVersion`、`clientId`、`clientToken` 均为空。Android 原生资源配置是否与示例同步、SDK 在初始化前是否存在数据处理、最终 APK 实际包含哪些依赖及其行为，均须针对发布 APK 核验。因此上面的接入时序是代码预期，不能代替对 SDK 实际行为的审查。

TapTap 对其 SDK 收集和处理的信息、用途、方式及权利说明，请以最终集成版本适用的官方文件为准：

- [TapSDK 合规使用说明](https://developer.taptap.cn/docs/sdk/start/compliance/)
- [TapSDK 隐私政策](https://developer.taptap.cn/docs/sdk/start/agreement/)

运营者须阅读并将最终 SDK 版本涉及的信息类别、处理目的、调用时机、共享对象、保存期限和用户权利说明准确补充到正式政策中。不得仅复制 SDK 的概括性清单，也不得将 SDK 处理描述成游戏自身处理。

## Android 权限清单（当前工程 Manifest）

当前 `native/engine/android/app/AndroidManifest.xml` 声明以下权限：

| 权限 | 当前用途判断 | 发布前核对 |
| --- | --- | --- |
| `android.permission.INTERNET` | 游戏联网及 TapTap 登录、合规服务通信 | 核对最终合并 Manifest 和 SDK 网络请求 |
| `android.permission.ACCESS_NETWORK_STATE` | 判断/使用网络状态，可能由 SDK 使用 | 向 SDK 供应方核实实际读取时机及用途 |
| `android.permission.ACCESS_WIFI_STATE` | 读取 Wi-Fi 状态，可能由 SDK 使用 | 向 SDK 供应方核实实际读取时机及用途 |

当前该 Manifest 未声明存储、通讯录、位置、电话、相机、麦克风等运行时敏感权限；最终以发布 APK 的合并 Manifest 和应用商店检测结果为准。权限是否由 SDK 触发、何时触发及其个人信息属性需进一步核实。`usesCleartextTraffic=true` 也应在正式包审查中确认是否确有必要。

## 信息保存、共享与安全

本地游戏存档保存在应用私有存储中；Android 系统备份行为需按最终配置确认。TapTap 账号和合规认证信息由 TapTap 相关服务按其政策处理，游戏会按上述流程传递账号 OpenID。当前仓库未发现自建游戏服务器或广告、统计 SDK 的明确接入，但必须对最终 APK 的完整依赖、网络行为及第三方组件进行复核后，才能对外作出“没有其他共享或处理”的承诺。

正式政策需由运营者补充并核实：受托处理方和其他接收方、跨境情况（如有）、具体保存期限或确定方法、数据安全措施、个人信息安全事件联系渠道，以及用户请求的受理与响应流程。

## 用户权利与撤回同意

当前 Android 接入代码包含撤回隐私同意的入口：撤回后清除本机记录的已同意版本、退出 TapTap 合规流程并登出，然后结束游戏；代码提示本地存档保留。玩家也可通过运营者公开联系方式咨询、更正、删除个人信息或撤回同意。撤回本机同意不等同于自动删除 TapTap 已处理的信息；相关请求如何转交或由玩家向 TapTap 提出，需由运营者确认后写入正式政策。

## 政策更新

正式政策须说明版本、生效日期、重大变更通知方式及必要时重新取得同意的方式。当前 Android 配置会使用隐私政策版本和 URL 判断是否需要重新展示同意流程；发布前须确认正式配置与线上政策版本一致。
